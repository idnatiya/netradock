Quick Start & Deployment

Pick your preferred deployment method. Docker Compose is strongly recommended for production VPS environments. 

# 1. Clone repository
git clone https://github.com/idnatiya/netradock.git && cd netradock

# 2. Prepare environment variables
cp .env.example .env
make hash  # Prompts for password, prints NETRADOCK_PASSWORD_HASH

# 3. Launch service
docker compose up -d --build

# Access web UI at http://127.0.0.1:8080
docker run -d \
  --name netradock \
  --restart unless-stopped \
  -p 127.0.0.1:8080:8080 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -e NETRADOCK_USERNAME=admin \
  -e NETRADOCK_PASSWORD="your-strong-password" \
  -e NETRADOCK_SECRET="$(openssl rand -hex 32)" \
  netradock
# Prerequisites: Go 1.26+, Node.js 22+
git clone https://github.com/idnatiya/netradock.git && cd netradock
make install
make build

# Run compiled static binary
NETRADOCK_USERNAME=admin NETRADOCK_PASSWORD="your-password" ./netradock
Production TLS & Proxy

Reverse Proxy Configurations

Always run Netradock behind HTTPS. Make sure your proxy forwards WebSocket connections and supplies real client IPs via headers. 

# /etc/caddy/Caddyfile
docker.yourdomain.com {
    reverse_proxy 127.0.0.1:8080
}

# In .env:
NETRADOCK_PROXY_HEADER=X-Forwarded-For
NETRADOCK_SECURE_COOKIE=true
server {
    listen 443 ssl http2;
    server_name docker.yourdomain.com;

    ssl_certificate     /etc/letsencrypt/live/docker.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/docker.yourdomain.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;

        # WebSocket support
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # Forwarded headers
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_buffering off;
        proxy_read_timeout 86400s;
    }
}
Defense in Depth

Hardened Security by Default

Because Docker socket access equates to root privileges on your host, Netradock treats security as a foundational requirement.

Stateless HMAC Tokens

HttpOnly, SameSite=Lax, and Secure cookie tokens. Instant revocation upon password or secret rotation.

Brute-Force Rate Limiting

Strict 5 requests/min per-IP limiter coupled with a global bucket prevent brute-force credential attacks.

CSRF Same-Origin Guard

Mutation routes (POST, DELETE) and WebSocket upgrades reject cross-origin requests automatically.

Distroless Image

Minimal container attack surface using Debian static distroless with zero package managers or shell utilities.
